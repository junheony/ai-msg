# BRIEF7c independent backend freshness review

Scope: `UsageService`, `CodexUsagePoller`, `codexLiveUsage`, `TurnRunner`, `engineLimits`, HTTP/server wiring, and their changed regression tests. This review did not modify source files, invoke a provider, run inference, or run the full suite. Findings were sent to the implementing agent and root immediately. The source fixes below have been independently inspected and their focused regressions pass; the separately reported full-suite failures came from a run started before those source fixes and require root’s fresh-process full-suite rerun.

## Findings and resolution

1. **P1 — A successful live refresh can immediately resurrect an older exhausted dashboard window.** `UsageService.overlay()` originally filled absent live windows with `obs.w.fiveHour ?? u.fiveHour`. In usage-deck mode, applying a complete live weekly reading of 3% used, then polling an older dashboard card with five-hour/weekly 100%, restored five-hour 100% and dated it as the fresh observation. The server refresh callback explicitly performs this poll after the live read. Reproduced using the real service with an injected in-memory dashboard; no external request. The implementing agent added a persistent `complete` flag to the observation, and rerunning that dated-card reproduction now keeps five-hour unknown and weekly 3%.

   **Resolved source-precedence case:** a dashboard card with missing/invalid `fetchedAt` must not retire a complete live observation. The old overlay policy treats undated non-down cards as authoritative. A second reproduction with `fetchedAt: null` replaced the same fresh weekly 3% with dashboard weekly/five-hour 100%. The final fix is scoped to complete GPT observations so existing Claude behavior stays intact. Independently rerun regressions cover older, equal-time, null-time, and invalid-time cards; all four preserve the live value and absent-window tombstone.

2. **P2 — A malformed present live window was silently interpreted as an absent window in a complete snapshot.** `parseCodexLiveUsage()` originally skipped invalid windows. A valid five-hour window plus weekly `usedPercent: 101` returned a five-hour-only result; `applyGptLive()` then erased a previously valid weekly window/limit. That conflated malformed data with a legitimate null/absent quota bucket. Reproduced directly against the parser. The implementing agent now rejects a malformed present window or unsupported duration; the same reproduction returns null. Legitimately absent/null windows can still be cleared by a complete valid response. The focused mixed valid/invalid parser regression independently passed; rejected responses use the existing timestamped fallback path without applying a complete replacement.

3. **P1 — An older in-flight success can clear a newer genuine quota cooldown.** New Codex/Hermes success branches unconditionally assigned `gptCooldownUntil = null`. With overlapping turns, A starts, B subsequently fails with an actual quota error, then A finishes successfully; A erases B's newer cooldown. A request already accepted before B failed does not prove that a new request can be admitted. This follows directly from the shared mutable cooldown and asynchronous runner; existing tests only cover sequential old failure → new success. **Source resolved:** each Codex/Hermes turn records a cooldown generation at start, genuine Codex failures increment it, and success clears only an unchanged generation. This also preserves same-clock-tick ordering. The new suspended-A/failing-B/released-A regression independently passed. Root’s earlier full-suite process began at 02:50:54, before the generation fix at 02:52:24, and also failed the complete-snapshot cases added during that run. Its module cache therefore exercised an inconsistent old-source/new-test snapshot. The implementer’s fresh TurnRunner run passed 117/117; the independent focused run also passed. No further source patch was needed.

## Other review results

- RPC client sends only `initialize`, `initialized`, and `account/rateLimits/read`; no thread/turn/login/reset-credit method is sent. Environment reuses `codexEnv`, preserving `CODEX_HOME` and dropping API-key overrides. Stderr/auth content is not logged; timeout and output bounds terminate the child. Fake-executable tests inspect the exact sent methods and auth/timeout behavior.
- Rollout fallback now keeps the observation's actual timestamp. The poller's monotonic watermark, displayed-card timestamp check, and success floor prevent ordinary historical 100% replay. A concurrent live request is coalesced and repeated attempts are throttled.
- Known paid credits prevent a successful turn from invalidating exhausted subscription windows. Current post-start exhausted readings are preserved, and absent live windows clear to unknown rather than invented zero. The complete-snapshot malformed-input issue above was the exception found.
- The success freshness floor is persisted atomically to private metadata and loaded on restart; a restart regression was added. This review did not read or write production metadata.
- The refresh GET is behind the existing authentication gate, and a test checks unauthorized refresh cannot invoke the callback. Normal GET does not force a refresh.
- Passed/estimated reset windows become unknown for engine routing, while current genuine exhaustion and cooldown behavior remain represented.
